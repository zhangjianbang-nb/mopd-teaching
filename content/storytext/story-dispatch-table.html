第一幕 · 一格只能落一个

阿珍的派单桌上有一张表：横轴是车型，纵轴是故障类型，格子里写着该叫哪位师傅。表是上一任前台留下的，用了七年，边角被机油浸成深褐色。阿珍每天早上拿抹布擦一遍，再拿红笔在当天的格子上打勾。

小周发现，同一辆车在表上只能落一个格子，可它往往同时有三四个毛病。一辆车同时有电路、发动机、漆面三个问题，旧表格只能把它归到“发动机组”。阿珍按表派了吴师傅，电路和漆面没人管，车修好一半。小周说：“不是师傅不行，是表格太粗。一辆车只配一个师傅，等于让一个人同时当电工、机修和喷漆工。”

阿珍把表翻过来，在背面画了一条线：左边写“车”，右边写“步”。她问小周：“你修一辆车，一共几步？”小周说：“看车，三十步到八十步。”阿珍说：“那为什么表格只给你一个格子？因为表格是按车分的，不是按步分的。”

这就是样本级路由：一辆车（一个样本）只选一个教师。样本级路由便宜，一次前向就够；但它把一辆车里所有 token 都交给同一个教师，电路 token 听到发动机师傅的话，漆面 token 也听发动机师傅的话。教师越自信，错得越整齐。

第二幕 · 把格子切开

阿珍把每个格子切成三行：诊断、拆解、装配。诊断行叫最懂症状的师傅，拆解行叫最懂结构的师傅，装配行叫最懂公差的师傅。同一辆车，三个师傅各说一段。小周第一次拿到这种工单，觉得像三张不同的处方叠在一起，但每一张都只写自己那一行。

电路诊断，陈师傅说：“先量启动瞬间的电压，不要先拆火花塞。”结构拆解，郑师傅说：“纵梁先上校正架，不要先动漆面。”装配，许师傅说：“漆面最后做，做完不要再开引擎盖。”

小周照着做，车一次修好。他问阿珍：“为什么不让一个师傅把三行都说了？”阿珍说：“一个师傅说三行，前两行对，第三行可能就成外行。三行分开，谁也别越界。”

这就是 token 级路由：不是按样本选教师，而是按每个 token 的域归属选教师。诊断 token 给诊断教师，拆解 token 给结构教师，装配 token 给装配教师。粒度细了，监督准了，但代价也来了：一次前向要跑三个教师，显存和延迟都涨。

老算在旁边打算盘：“三个师傅同时上车，举升机不够。你能不能把三行合成一次？”阿珍说：“合成一次，就得有一个师傅先说三行，又回到老路。要么多花举升机，要么少准一点，没有白拿的细粒度。”

第三幕 · 红笔加权

小周发现自己对电路最生，对漆面最熟。阿珍用红笔把“学生不会”的格子圈大：电路格子占三行，漆面格子只占半行。吴师傅说：“你这是偏心。漆面也是活，凭什么少讲？”阿珍说：“不是偏心，是按差距分课。你已经会的，讲一遍就够；你不会的，讲三遍还嫌少。”

红笔的规则来自学生的损失：哪个 token 上学生与教师的差距大，哪个 token 的权重就高。差距不是“教师有多强”，是“学生离教师有多远”。一个教师再强，学生已经会了，权重也应当降下来；一个教师不那么强，但学生正好卡在那里，权重反而要高。

小周问：“那红笔圈多大算合适？”阿珍说：“圈到学生能跟上为止。圈太小，学生学不动；圈太大，同一个师傅反复讲同一段，学生听烦了，反而学不进去。”

他们试了一个月：红笔按周重算，不按天；每个格子的权重上限设一个阈值，超过就削平。小周电路分从 42 涨到 61，漆面分没掉，发动机分掉了 2 分。阿珍说：“这就是代价。你把课时给电路，发动机就少听两节。预算不是无限的。”

第四幕 · 表格的边界

新表格用了三个月，阿珍发现两个问题：一是格子边界模糊，有些故障跨三行；二是红笔圈得太大，学生被同一个师傅反复讲同一段，反而学不动。她把红笔改成按周重算，格子边界改成“按 token 归属”而不是“按故障名”。

边界模糊的例子：一辆车的“发动机异响”既可能是电路（点火）、也可能是结构（机脚）、还可能是装配（皮带张紧）。旧表格把它归到发动机组，新表格把它拆成三个 token 段，每段问对应师傅。阿珍说：“故障名是人起的，token 是车自己走的。按故障名分，永远有跨界的；按 token 分，跨界也能切开。”

红笔太大的例子：小周电路差，阿珍把电路格子圈了三行，陈师傅每节课都讲同一段“先量电压”。小周听到第五遍，开始走神。阿珍把权重上限从 3.0 降到 1.8，陈师傅改成“讲一段、练一段、换一段”，小周反而学得快。她说：“权重是给差距的，不是给师傅的。师傅讲得多，不等于学生学得多。”

表格还有第三个边界：路由器本身也要训练。阿珍的红笔是人工规则，真实路由器靠学生与教师的 KL 训练：哪个教师能降低学生在这个 token 上的 KL，就给哪个教师更高的权重。人工规则能起步，但不能代替路由器的在线学习。

年底，阿珍把旧表格收进抽屉，新表格挂在墙上。她在表格底下写了一行小字：一格一个师傅，是样本级；一行一个师傅，是 token 级；红笔圈差距，不圈师傅；格子会跨界，token 不会撒谎。

第五幕 · 跨店会诊

第二年，车行和城东分店联了网。分店遇到一辆怪车：冷车正常，热车方向盘抖，抖的时候仪表盘还闪一下。分店的师傅说是发动机脚垫，总店的陈师傅说是电路搭铁，两边各说各的，谁也不服谁。阿珍把两边的工单并排放在桌上，发现两个人说的不是同一个 token：分店师傅说的是“抖”，陈师傅说的是“闪”。

阿珍没有二选一，而是把单子拆成两半：抖的那一半给分店师傅，闪的那一半给陈师傅。两个人各修各的一半，车好了。小周问：“为什么不让他们商量一个共同答案？”阿珍说：“商量出来的共同答案，往往是两个人各退一步的折中，折中不一定对。让他们各管各的 token，比让他们吵出一个答案更准。”

可分店师傅不服气：“一辆车拆成两半，谁来保证两半能装回去？”阿珍说：“装配那一段，另派一个人。三个人各管一段，最后一个人负责合。合的人不看谁嗓门大，只看三段接口对不对得上。”

这就是软路由的雏形：不是把整辆车硬派给一个师傅，也不是把每个 token 硬切给一个师傅，而是给每个师傅一个“话语权比例”。抖的 token 上，分店师傅占七成，陈师傅占三成；闪的 token 上，陈师傅占八成，分店师傅占两成。两个人的话都进工单，但权重不同。

老算问：“七成三成，怎么算出来的？”阿珍说：“看谁在这个 token 上让学生进步大。分店师傅修抖修得多，抖的 token 上他的权重就高；陈师傅修闪修得多，闪的 token 上他的权重就高。权重不是资历，是最近的有效性。”

他们试了一个月：硬路由（一格一个师傅）返工 2.4 辆/周；软路由（每个 token 按权重混合）返工 1.1 辆/周，但每次修车要多跑一个师傅，工时涨了 18%。老算说：“软路由准，但贵。你要看多修一辆车赚的钱，够不够付多跑的工时。”

小周问：“那能不能只在高风险 token 上用软路由，其他 token 用硬路由？”阿珍说：“可以。这叫混合路由：简单的 token 走硬路由，省时间；跨域、模糊、容易出错的 token 走软路由，多花一点算力买准确。路由不是一刀切，是按风险分层。”

这就是 soft routing 与 hard routing 的取舍：hard routing 便宜、可解释、易部署，但在跨域 token 上容易一刀切错；soft routing 准、能表达“两个师傅都有道理”，但要多跑教师、多花算力。真实系统常用混合方案：先硬路由找候选，再在候选上做软加权；高风险样本才走全软路由。

第六幕 · 路由日志

阿珍有一个黑皮本，专门记路由日志：日期、车型、故障、派了谁、权重多少、修完返工没有。记了半年，她翻出一个规律：每次派给许师傅的漆面单，返工率都低；每次派给许师傅的结构单，返工率都高。她把这条规律圈起来，在旁边写：“许师傅在漆面是老师，在结构是外行。路由不能只看‘谁有空’，要看‘谁有资格’。”

又翻了半年，她发现另一个规律：有三个格子的单子，永远派给同一个人——陈师傅。不管什么车型、什么故障，只要落在那个格子，阿珍的手就自动写“陈师傅”。她问自己：“是陈师傅真的最合适，还是我懒得想？”她把那三个格子的单子抽出来，重新按“最近三个月谁修好过”排了一遍，发现有两个格子其实该派给吴师傅。

老马说：“这叫路由坍塌：路由器偷懒，把所有 token 都派给同一个教师。教师池看起来很大，实际只用了一个。坍塌不一定是坏事，如果那个教师真的最强；但大多数时候，它是因为路由没有探索，或者权重被一个教师垄断。”

阿珍给路由加了两条规矩：一是每个教师每周至少接一单“非自己主域”的探索单，看看有没有被埋没的能力；二是任何一个格子的单子，不许连续三周派给同一个人，除非日志里写明“另外三个人都试过，确实不如他”。

小周问：“探索单要是修坏了怎么办？”阿珍说：“探索单只派低风险车，修坏了老马兜底。你不给新师傅上车的机会，永远不知道他会不会修。但探索要有边界：低风险、可回退、有人看着。”

半年后，路由日志厚了三本。阿珍把返工率画成一条线：硬路由 2.4，软路由 1.1，加探索后 0.9，加资格表后 0.7。她在最后一页写：路由不是把单子送出去，是把单子送给对的人；对的人不是永远同一个人，是每个域上最近修得好的人。

这就是路由坍塌与路由探索：路由器会因训练信号、权重初始化、教师同质化而退化成“只选一个教师”；退化会让教师池的有效容量消失，也会让被冷落的教师永远得不到验证。治理办法是探索配额、资格表、日志审计、按域重排；探索必须低风险、可回退、有验证器兜底。路由的目标不是“每次都选最稳的”，是“在预算内让每个 token 找到最有资格的教师”。

把故事翻译成技术语言

旧表格一格一个师傅，是样本级路由：一个样本只选一个教师，便宜但粗。新表格把格子切成诊断、拆解、装配三行，是 token 级路由：每个 token 按域归属选教师，准但贵。红笔圈“学生不会”的格子，是能力差距权重：按学生与教师的差距分配监督，不按教师强弱。红笔太大导致反复讲同一段，是路由坍塌/权重过载；格子边界模糊，是 hard routing 把连续归属压成离散标签；路由器本身要靠 KL 训练，人工红笔只是冷启动。

真实系统里，token 级路由在推理时要跑多个教师，显存和延迟都是成本；路由概率是软的，不是表格里的硬格子。故事把 soft routing 压成了 hard routing，是为了让“一格只能落一个”和“一行可以落三个”的差别一眼看见。
