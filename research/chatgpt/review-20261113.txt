1. 文献结构审查：目前有一个分类隐患

我建议不要把这 28 篇全部归为「MOPD 论文」。

它们实际上包含至少五种不同性质的研究：

文献类型	代表论文	在教学站中的作用
蒸馏基础	Distilling the Knowledge in a Neural Network	建立知识蒸馏基础
On-Policy KD	MiniLLM、GKD、DistiLLM	建立在线蒸馏机制
能力整合	MOPD、Open-MOPD、CA-MOPD	建立多教师能力整合主线
Agent 蒸馏	MapCoder-Lite、MemOPD、DivOPD	扩展到长程交互和工具调用
相邻技术与工业实践	MiMo-V2-Flash、Micius-Flash、Open-SWE-Traces	研究工程应用、数据和系统

这里有一个重要的分类修正：

相关技术不等于 MOPD 的直接技术组成部分。

例如：

Memory Post-Training 不必然属于 MOPD。
Self-Correction 不必然属于 On-Policy Distillation。
Verifiable Curriculum 不必然属于 Multi-Teacher Distillation。
Agent Policy Distillation 也不必然需要多个教师。

建议给每篇论文增加两个标签：

Core：直接研究 MOPD 或其必要机制。
Adjacent：研究与 MOPD 密切相关、但不直接属于 MOPD 的技术。

否则教学站容易形成一个错误印象：所有 2026 年的 Agent 后训练研究都是 MOPD 的演进。

2. 我认为文献中最值得关注的技术关系

以下几组论文应该建立明确的交叉引用，而不是简单按照年份排列。

A. MiniLLM → GKD → DistiLLM

这组解决的是：

学生应该如何在自己的生成分布上接受教师监督？

其中：

MiniLLM：Reverse KL、Mode-seeking。
GKD：学生采样与多种散度目标。
DistiLLM：蒸馏效率和训练稳定性。

需要特别注意：MiniLLM 的 arXiv 首次提交是 2023 年，会议发表属于 2024 年。GKD 也存在预印本年份与会议发表年份的区别。

你的年份字段应该统一采用一种口径，最好同时保存：

first_arxiv_date、`conference_year`、`last_revision_date`。

否则演进时间线会产生人为错位。

一个动作虽然来自学生自己的 rollout，但如果教师评分时使用了不同的记忆状态，它就不再是严格意义上状态对齐的监督。

这是非常值得单独制作理论卡的概念。

3. 这份文献目录还存在四个值得补强的地方
问题一：经典蒸馏理论与现代 LLM 蒸馏之间存在断层

你目前是：

2015 Hinton → 2022 EKT-Code → 2023/2024 LLM KD。

中间建议补充：

Knowledge Distillation 的不同目标函数。
Sequence-level Knowledge Distillation。
Policy Distillation。
Student-generated Distribution。
Offline 与 On-Policy 的理论差异。

否则学生会认为 MiniLLM 是突然出现的技术，而不理解它为什么要改变传统 KD 的训练分布。

问题二：缺少多教师融合的基础理论对照

建议补充专门的理论材料：

Ensemble Distillation。
Multi-Teacher Knowledge Distillation。
Expert Aggregation。
Mixture-of-Experts 与 Teacher Routing。
Parameter Merging。
Gradient Surgery / Multi-Task Optimization。

注意：这些不一定都需要作为核心论文，但必须作为对照方法。

特别是 Parameter Merging。

MOPD 的重要价值之一，就是提供了不同于参数合并的能力整合路径。没有这个对照，学生很难理解为什么需要 MOPD。

你收集了：

但是不要把这些论文全部标记为 MOPD。

问题四：缺少明确的负面结果和失败案例

目前文献看起来偏向提出新方法、展示性能提升。

建议增加一个专门的失败案例集合：

多教师训练后某个领域能力下降。
学生已经超过教师，却仍然受到强监督。
教师之间相互矛盾。
Token 数量导致优化权重失衡。
长轨迹导致训练预算被少数任务占据。
Memory 压缩导致状态错位。
Verifier 无法正确识别学生的真实能力。

其中 Open-MOPD 和 CA-MOPD 已经提供了很好的案例。
